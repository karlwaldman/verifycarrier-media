## Carrier research in ChatGPT

This is a walkthrough of VerifyCarrier carrier research in ChatGPT, using actual responses captured from the connected production MCP tools. We will find a carrier, inspect the public evidence, replay the saved result, and show the weekly limit and recovery path. The carrier evidence in this demonstration was originally retrieved on October first. It is not presented as a fresh source check.

## 1. Find the intended carrier

First, search by company name. The production search tool returned one candidate: Majesty Auto Sales L L C, U S D O T two nine three zero three six six, in Newberry, South Carolina. The user can confirm this is the intended business before researching it. Searching does not consume the weekly carrier lookup allowance.

## 2. Read the dated public evidence

The evidence tool returns the previously saved public result for this carrier. It includes a retrieval timestamp and reports partial evidence. Carrier identity is available. The insurance source is empty, the U C C source reports no match, and several safety fields are null. Those states are not converted into clean findings. No match does not prove there are no liens, and empty insurance data does not establish whether coverage exists. VerifyCarrier leaves onboarding and booking decisions to the user.

## 3. Replay the same carrier

Next, ask for the snapshot of the same carrier. The live response contains the same structured public evidence and the same original retrieval timestamp. Snapshot and evidence share one rolling seven day allowance. Repeating the saved carrier returns the dated result instead of presenting a new source check.

## 4. Show the weekly limit and recovery

Requesting a different carrier returns the weekly allowance used error. The response includes an exact retry time and a link to continue researching on VerifyCarrier. In this capture, the allowance renews on October eighth at seven forty two U T C. This is the actual recovery response from the production tool, not a simulated success.

## 5. Reject malformed input

For a negative case, pass a U S D O T number with leading zeros. The connected tool rejects the parameters at schema validation. It does not turn malformed input into a carrier result. This demonstrates a clear failure response before research starts.

## 6. Continue on VerifyCarrier

The website handoff is the next step for detailed filings, source records, saved reviews, higher volume A P I access, and continuous monitoring. Those capabilities remain in VerifyCarrier. Following the link does not itself activate monitoring, approve a carrier, or book a load. This walkthrough showed real production tool responses, including source gaps, saved evidence, quota recovery, and invalid input.
